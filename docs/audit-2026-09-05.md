## Ranked candidates

### High

#### H1. Named Profile has three on-disk owners

**Smell:** reconstructed meaning, parallel vocabularies, convention-enforced
validation.

**Evidence (rung 2 unless marked):**

- MCP front: `session_layout.py:25` (`~/.cache/tool-proxy/browser-tools`),
  `session_layout.py:39-41` `profile_dir(name)`; profile dirs made 0o700 at
  `persistent_browser.py:541`.
- CLI front: `lifecycle.py:78-94` `profiles_root()` defaults to
  `/tmp/browser-tools-profiles`; dir created with default umask at
  `lifecycle.py:401-403`; login-bearing dirs under `/tmp`.
- Camoufox MCP tool: `camoufox_session.py:28-45` keeps a third form, a
  Playwright storage-state JSON under its own copy of the cache path.
- Name validation exists in two places with two rules
  (`profile_catalog.py:177-194` for delete only;
  `camoufox_session.py:29,43` for Camoufox only) and nowhere on the create
  path: `persistent_browser.py:280-282` and `browser_session.py:82` pass the
  raw name to `profile_dir`.
- Rung 4: `PersistentChromeController(profile="../../escape", isolated=False)`
  resolves `user_data_dir` to `<tmp>/escape`, outside `profiles_dir()`, and
  `state_path` to `CACHE_DIR/profile_../../escape.json` (scratch script,
  CACHE_DIR patched to a temp dir).
- `bt launch --profile dev`, `use_browser_session(profile="dev")` and
  `launch_camoufox(profile="dev")` therefore name three different
  identities. `README.md` "Keeping login state across calls" describes one.

**Proposal:** one owner. `session_layout` exposes a validated `ProfileName`
(or `profile_dir(name)` that raises on anything outside
`[A-Za-z0-9._-]+`, `.`/`..` excluded) and one root with 0o700 creation.
`lifecycle.profile_user_data_dir` and `camoufox_session._camoufox_state_path`
call it; `BROWSER_TOOLS_PROFILES_DIR` stays as the override of that one
root. `profile_catalog.delete_profile` keeps only the "is a directory under
the root" check.

**Payoff:** one login state per name across both fronts; traversal closed at
one seam; profiles leave world-writable `/tmp` (rung 3, traced from the
three roots).

**Churn:** `session_layout.py`, `lifecycle.py`, `camoufox_session.py`,
`profile_catalog.py`, `persistent_browser.py`, `browser_session.py`, plus
`test_cli_lifecycle.py`, `test_profiles.py`, `test_camoufox.py`, README
(rung 1, estimated, about 8 files). Existing CLI profiles under `/tmp` need a
one-line migration note.

#### H2. A repository's `.browser-tools.json` reaches the controller unvalidated

**Smell:** convention-enforced consistency (validation lives at two of three
entry points); security.

**Evidence:**

- `session_store.py:81-87` walks from the project dir up to `/` and takes
  the first `.browser-tools.json` or `.tool-proxy/browser-tools.json`
  (`:33-36`).
- `session_store.py:102-164` builds a `PersistentChromeController` straight
  from the file: `endpoint`/`browser_url` at `:118,158`, `profile` at `:159`.
- `validate_local_endpoint` is called only from
  `browser_session.py:66` (`attach_browser`) and `:329`
  (`use_browser_session`), never on the project-preference path.
- Rung 4 (scratch): with `TOOL_PROXY_PROJECT_DIR` pointing at a temp dir
  whose `.browser-tools.json` says `"endpoint": "http://203.0.113.5:9222"`,
  `create_project_preferred_controller().browser_url` is that URL while
  `validate_local_endpoint` rejects it. A config placed in an ancestor
  directory of the project dir is also picked up.
- `docs/rfc/01...rfc.md:166` says project config "MUST NOT be able to
  redirect an existing instance"; `:244` requires loopback-only CDP.
- Consequence (rung 3): a cloned repository can point every tool call,
  including the MCP Subprocess's `--browserUrl` and the tab enumeration in
  `process_utils.enumerate_tabs`, at a remote host, and can name a
  login-bearing Named Profile (H1) for the agent to drive.

**Proposal:** `ProjectBrowserConfig.from_path` (or
`create_controller_from_browser_config`) becomes the single validating
owner: loopback check on `endpoint`/`browser_url`, profile-name check (H1),
`channel` in the known set. Stop the upward search at
`resolve_project_root()` rather than `/`.

**Payoff:** repository content can no longer choose the browser or the
profile; the two `browser_session` call sites drop their own checks (rung 3).

**Churn:** `session_store.py`, `browser_state.py`, two call sites in
`browser_session.py`, `test_auth_identity.py`/`test_session_lifecycle.py`
(rung 1, about 5 files).

#### H3. `--user-data-dir` regex stops at the first space; mode='real' cannot re-attach on macOS

**Smell:** correctness; one parser, two consumers with different failure
modes.

**Evidence:**

- `process_utils.py:30` `_USER_DATA_DIR_PATTERN = --user-data-dir=(\S+)`.
- Rung 4: against a real Chrome Canary command line the match is
  `/Users/kevin/Library/Application`;
  `resolve_system_profile_dir("canary")` returns
  `.../Library/Application Support/Google/Chrome Canary`.
- Consumers: `pid_holds_user_data_dir` (`process_utils.py:386-408`) feeds
  LiveChrome's `holds_dir` (`live_chrome.py:75-77`);
  `persistent_browser.py:547-561` refuses a second launch only when
  `holds_dir is True`; `_try_reuse_existing_chrome` (`:690-697`) reuses only
  when `holds_dir is True`; `handle_attach_browser` coherence check
  (`browser_session.py:110-128`).
- Traced flow (rung 3): after `close_browser` in mode='real' the state
  file is unlinked (`persistent_browser.py:201`) and the user's Chrome keeps
  running. The next call finds no usable state, `holds_dir` is False, the
  guard is skipped, `clean_stale_singleton_lock` is a no-op (lock PID alive),
  a second Chrome is launched into the same directory, Chrome hands off to
  the running instance and exits, `wait_for_devtools` times out three times
  (`:633-673`, 30 s) and the call fails with the "failed to expose its debug
  port" message. The same truncation hits any profile path with a space.
- The vendored core documents the same limitation for its own scan
  (`core/registry.py:135-141`) and accepts it because its session dirs never
  contain spaces; the MCP front's system-profile dirs always do on macOS.

**Proposal:** `process_utils` owns one argv reader that returns the full
value: match `--user-data-dir=(.+?)(?=\s--|\s*$)` over `ps -ww -o command=`,
or read `sysctl kern.procargs2` on darwin. Add a regression test with a
spaced path.

**Payoff:** mode='real' reuse and the attach coherence check work on macOS;
the 30-second duplicate-launch failure disappears (rung 3).

**Churn:** `process_utils.py` and `tests/test_close_and_real_mode.py` /
`test_profile_liveness.py` (rung 1, 2-3 files).

#### H4. The MCP Subprocess is unpinned (`npx -y chrome-devtools-mcp@latest`) and its text format is the Active Page contract

**Smell:** mirrored artifact (a remote package's output format re-encoded
as regexes), supply chain.

**Evidence:**

- `chrome_config.py:31`, `chrome_utils.py:52`,
  `persistent-session-template.mjs:21`: `@latest` resolved at every Daemon
  spawn.
- `page_selection.py:39-40` parses `N: url [selected]` lines out of
  `list_pages` text; `browser_session.py:566-584` parses the same lines
  again; `screenshot_utils.py:26-64` probes two historical response shapes
  for the same reason.
- `mcp_daemon.py:187-195` pins `protocolVersion` to `2024-11-05` while the
  server floats.

**Proposal:** one `MCP_SUBPROCESS_SPEC = "chrome-devtools-mcp@<exact>"`
constant owned by `chrome_config` (Dependabot can bump it); page-list
parsing moves into `mcp_response.parse_page_list()` so the format
dependency has one owner (see L4).

**Payoff:** a `latest` bump can no longer change tool behavior or break
Active Page re-resolution between two invocations; the supply-chain surface
becomes an explicit, reviewable version (rung 2).

**Churn:** 3 files for the pin; page-list owner touches
`page_selection.py`, `browser_session.py`, `mcp_response.py` and their
tests (rung 1, about 6 files).

#### H5. The optional MCP front has no shipped entry point, and the docs describe the retired one

**Smell:** dead surface; mirrored artifacts (README, CONTRIBUTING, RFC) out
of step with the code.

**Evidence:**

- `pyproject.toml:71-74` ships `browser-tools`, `bt`
  (`cli:main`) and `browser-tools-profiler` only.
- `browser_session.create_tool_proxy_handlers` (`:860-904`) is the only
  entry to Session Tool Dispatch, Session Resolver, the controller, the
  Daemon, McpBroker and PageSelection. Graph inbound callers: one, the
  test `test_e2e_backend_seam.py` (rung 2, `trace_path`).
- `docs/tool-proxy-retirement.md:29` says the retired adapter imported
  `browser_tools.browser_tools_session`; no such module exists.
  `README.md:74` and `CONTRIBUTING.md:43-44` still name it as the CLI entry
  point; `profiler.py:13` names an `mcp_server` module that does not exist.
- `README.md:45-46` Quick Start: `browser-tools --isolated navigate --url
  ...`. Rung 4: exits 2, "invalid choice: 'navigate'"; the parser has no
  `--isolated`.
- RFC `:184-185` promises "the MCP daemon becomes an OPTIONAL front"
  that "remains for harnesses that cannot run a CLI".

**Proposal:** decide the MCP front's status. Either ship it (a
`browser-tools-mcp` console script that wraps `create_tool_proxy_handlers`
in a stdio MCP server) or state in README/CONTEXT that the session stack is
a library used by an external adapter. In both cases rewrite README "Quick
Start" and "Architecture" and CONTRIBUTING "Architecture" against the
current module set (`cli`, `lifecycle`, `one_shot`, `passthrough`,
`events`, `list_verbs`, `curated`, `core/`).

**Payoff:** a user following the README gets a working command; 5.5k lines
either gain an entry point or are labelled as what they are (rung 2 for the
line count, from the module sizes).

**Churn:** docs only, or docs plus one new module and a pyproject line
(rung 1).

### Medium

#### M1. Two CDP clients, two `CDPError` types, two `send` signatures

**Smell:** duplicated ownership; the RFC's own invariant is not met.

**Evidence:** `cdp_client.py:36-158` (`send(method, params, timeout)`,
returns result, raises `CDPError(BrowserToolsError)`, no session id) is used
by CDPRuntime (`cdp_handler.py:396-404`), Interstitial Detection and
screencast. `core/cdp_client.py:35-95` (`send(method=, params=,
session_id=)`, raises `core.errors.CDPError` with code/message, or
`ConnectionError`) is used by One-Shot Session, passthrough, events,
list_verbs, curated.screenshot, the supervisor and the profiler. RFC `:97`:
"layer 2 tools MUST call the same CDP client `send` path the passthrough
uses". `cdp_handler.py:89-104` and `screencast.py:33-45` import the
first client's error class lazily to work around script mode (see L2).

**Proposal:** CDPRuntime adopts `core.cdp_client.CDPClient` over a
flattened `Target` session (the same attach One-Shot Session already
performs); `_safe_cdp_send`/`_cdp_call` map `core.errors.CDPError`. Delete
`cdp_client.py`.

**Payoff:** one transport, one error type, target selection for the handler
transport (unlocks M9); 253 lines and one test file removed (rung 2).

**Churn:** `cdp_handler.py`, `screencast.py`, `interstitial.py`,
`curated.py`, `__init__.py` exports, `test_cdp_client.py`,
`test_new_tools.py` fakes (rung 1, about 8 files; medium risk, the daemon's
frame-event subscriptions must move to the session).

#### M2. Owned-Chrome and Daemon teardown each have several implementations, not all guarded

**Smell:** duplicated ownership; the PID-recycle guard is applied on some
paths only.

**Evidence:**

- Guarded: `persistent_browser.quit_owned_chrome` (`:105-148`, start-time
  re-check), `close_active_session` (`:186-196`), session reaper
  (`session_reaper.py:110-116`), `lifecycle._terminate_verified`
  (`:652-667`).
- Unguarded: `close_owned_browser` (`persistent_browser.py:456-458`)
  SIGTERMs `state.pid` with no `chrome_owned`, `is_owned_profile_dir` or
  start-time check; its only caller is the headless-to-headed promotion
  (`browser_session.py:733`, graph-confirmed). A state written by
  `_try_reuse_existing_chrome` for a user-launched Chrome on the same dir
  carries `chrome_owned=False` and a live `pid` (`:704-710`), and that
  Chrome is the one killed (rung 3).
- Daemon idle/shutdown path: `mcp_daemon.py:131` calls
  `quit_owned_chrome(chrome_pid, chrome_user_data_dir, None)`; the
  supervisor never passes `chrome_started_at` (`daemon_supervisor.py:270-279`),
  so the 30-minute idle quit (`mcp_daemon.py:220-225`) has no PID-recycle
  guard on the one path that runs hours after the PID was recorded.
- `profile_catalog.delete_profile` (`:202-204`) terminates the SingletonLock
  PID without `pid_holds_user_data_dir`.
- Daemon stop is written three times: `daemon_supervisor.stop_only`
  (`:192-217`), `close_active_session` (`persistent_browser.py:178-183`),
  `close_owned_browser` (`:453-455`), although `daemon_supervisor.py:10-13`
  claims to own the Daemon process.

**Proposal:** `quit_owned_chrome(state: BrowserState)` is the only Chrome
teardown (it reads pid, dir, owned flag and start time from the state);
`McpDaemonSupervisor.stop_only` is the only Daemon teardown; the Daemon
receives `--chrome-started-at` and passes it through. `close_owned_browser`
and `close_active_session` become two-line compositions.

**Payoff:** every kill path re-verifies identity and ownership; three
copies of file cleanup go away (rung 3).

**Churn:** `persistent_browser.py`, `mcp_daemon.py`,
`daemon_supervisor.py`, `profile_catalog.py`, `test_close_and_real_mode.py`,
`test_persistent_browser.py` (rung 1, about 6 files).

#### M3. Interstitial results cross the socket as prose and are re-detected three ways

**Smell:** reconstructed meaning (three detectors), parallel vocabulary
(structured result vs. substring).

**Evidence:** the Daemon runs Interstitial Detection and appends formatted
text (`mcp_daemon.py:483-515`); the session adapter decides
headless-to-headed promotion by `"auth_wall" in text`
(`browser_session.py:628-640`). Rung 4: `text_response("docs: the auth_wall
detector")` signals promotion. Camoufox has its own detector with its own
type names (`camoufox_session.py:375-401`), unrelated to
`detect_interstitial.js`. `curated.detect` returns the structured dict the
Daemon throws away (`curated.py:261-284`).

**Proposal:** `mcp_response` owns an `interstitial` field on the envelope
(structured detections beside the text); Session Tool Dispatch reads the
field; the Camoufox Automation Backend runs
`interstitial.get_detection_script()` through `page.evaluate` and returns
the same shape.

**Payoff:** one detection policy for both engines, promotion keyed on data
not prose, `bt detect` and the MCP path report identically (rung 3).

**Churn:** `mcp_response.py`, `mcp_daemon.py`, `browser_session.py`,
`camoufox_session.py`, `test_interstitial.py`, `test_session_lifecycle.py`
(rung 1, about 6 files). The frozen MCP surface allows additive fields.

#### M4. Daemon spawn cannot see the Daemon die; every early exit is a 30-second blank timeout

**Smell:** correctness/robustness; the supervisor's interface hides the
failure it exists to report.

**Evidence:** `daemon_supervisor.py:282-289` discards the `Popen` handle and
sends stderr to `DEVNULL`; `:294-311` polls the socket for 30 s. Exits that
happen before the socket is bound: MCP init failure
(`mcp_daemon.py:196-199`), spawn failure (`:180-182`), argparse rejection
of `--mode` (`:543-545`; `attach_browser` forwards any string,
`browser_session.py:71,138`), AF_UNIX path over 104 bytes
(`session_layout.py:49-51` derives from `$HOME` and the profile name; the
test suite works around this limit at `test_mcp_daemon.py:26-31`,
production does not), and the `bind` race before `chmod`
(`mcp_daemon.py:233-235`). The user sees "Timed out waiting for MCP daemon to
start (waited 30s)" (rung 3).

**Proposal:** keep the handle, `poll()` inside the wait loop, and raise with
the exit code; write Daemon stderr to `CACHE_DIR/<key>.daemon.log`; validate
`mode` in `handle_attach_browser`; set `umask(0o077)` around `bind` and
check the socket path length at `session_layout`.

**Payoff:** failures surface in under a second with a reason (rung 3).

**Churn:** `daemon_supervisor.py`, `mcp_daemon.py`, `browser_session.py`,
`session_layout.py` (rung 1, 4 files).

#### M5. Recoverable-transport classification is string matching against another module's messages

**Smell:** convention-enforced consistency.

**Evidence:** `daemon_supervisor.is_recoverable_daemon_error` (`:324-342`)

`DEFAULT_CHANNEL`; the guide is generated from the parser (or the drift
test extends to the guide).

**Payoff:** adding a tool or engine is one edit; the Inspect Mode message
cannot lie (rung 2). **Churn:** about 8 files, low risk (rung 1).

#### M7. `stealth` is a pass-through argument threaded through six modules and never used

**Smell:** pass-through argument; configuration sprawl.

**Evidence:** 39 mentions across `browser_session.py`, `session_store.py`,
`persistent_browser.py`, `daemon_supervisor.py`, `mcp_daemon.py`,
`cdp_handler.py`; `cdp_handler.py:302-307` documents that nothing reads it;

`session_layout.py:98`.

**Proposal:** accept `stealth` at the frozen MCP surface, record it in the
config dataclasses for compatibility, and stop passing it below
`browser_session`. Drop the dead `source`/`isolated` parameters.

**Payoff:** four signatures and one CLI flag shrink; the daemon command line
loses a no-op flag (rung 2). **Churn:** 6 files, mechanical (rung 1).

#### M8. Curated CLI verbs bind to tab 0 and rebuild a full CDPRuntime per invocation

**Smell:** parallel vocabularies for "which page" across the two one-shot
transports; shallow reuse of a deep module.

**Evidence:** `curated._cdp_handler_session` (`:119-149`) builds a
`CDPHandler` whose runtime connects through `get_page_ws_url(browser_url)`
with `page_index=0` (`cdp_handler.py:399`, `cdp_client.py:234-253`); none of
`snapshot`, `click`, `fill`, `wait-*`, `detect`, `frames`, `storage`,
`screencast` accept `--target`/`--url` (`cli.py:190-257`), while
`screenshot`, the raw line, `wait` and the list verbs do. Each verb also
runs `Page.enable`, `Runtime.enable` and `Page.getFrameTree`
(`cdp_handler.py:407-411`) before doing anything (rung 3).

**Proposal:** after M1, CDPRuntime takes a resolved target (from
`one_shot`'s resolver) instead of a browser URL; the curated verbs gain the
same `--target`/`--url` slot.

**Payoff:** multi-tab instances become usable from the curated verbs; one
target-selection vocabulary (rung 3). **Churn:** `curated.py`, `cli.py`,
`cdp_handler.py`, tests (rung 1, 4 files; depends on M1).

#### M9. Tool-argument file paths resolve against the Daemon's cwd, and storage output prints cookie values

**Smell:** exposed implementation detail (the Daemon's cwd); security.

**Evidence:** the Daemon runs with `cwd=BROWSER_TOOLS_ROOT`
(`daemon_supervisor.py:284`), so a relative `path`/`dir` from `export_pdf`
(`cdp_handler.py:1044-1067`), `screenshot_element` (`:1137-1145`) and
`screencast_stop` (`screencast.py:185-190`) writes into the package
checkout or site-packages parent. `get_frame_storage` emits the first 50
characters of every cookie value (`cdp_handler.py:809-817`) into the agent
transcript (rung 3).

**Proposal:** the request envelope carries the caller's cwd (or the Daemon
refuses relative paths with a clear error); cookie values are redacted
unless `reveal_values=True`.

**Payoff:** no stray files under the repo; session cookies stop appearing
in logs by default (rung 3). **Churn:** 3 files plus `daemon_client.py`
(rung 1).

## Considered and rejected

- **CDPRuntime / CDPHandler split**: deep enough as designed; only the
  forwarding layer (L6) is flagged.
- **One-Shot Session, LiveChrome, `tool_registry`, `mcp_response`,
  `native_snapshot`, `native_interaction`**: small interfaces over real
  behavior; they pass the deletion test and are the models the rest should
  follow.
- **`SessionDispatchContext`'s single-element lists**: internal mutable
  cells; replacing them is cosmetic.
- **`lifecycle.py` calling `core.registry._load_registry` and friends
  (10 `reportPrivateUsage` ignores)**: forced by the vendoring rule and
  contained in one module; a `registry_ext` adapter would only move it.
- **`ps`-based process inspection in `process_utils`**: cost is bounded
  and `live_chrome` already gates the expensive branch behind
  `verify_holds_dir`.
- **`_is_named_profile`'s 16-hex-character heuristic**
  (`profile_catalog.py:25-44`): a human name of exactly 16 hex characters
  is misclassified; rare enough to note, not rank.
- **Two registries/profile roots for CLI vs. MCP front as a whole**: the
  RFC chose `/tmp` semantics for the vendored registry (Question 5); only
  the profile identity (H1) is a drift, the registry location is a decision.

## Per-area summary

### 1. Design smells (deepen and drift)

The modules the recent refactors produced (One-Shot Session, LiveChrome,
PageSelection, McpBroker, Tool Dispatch, Session Resolver, native
snapshot/interaction) are deep and hold their seams. The debt sits between
them: the Named Profile concept has three owners (H1), the CDP client has
two (M1), Chrome/Daemon teardown has several (M2), Interstitial results are
re-derived from prose (M3), routing data leaks out of `tool_registry` (M6),
and one argument is threaded through six modules for nothing (M7). Deepen
findings are mostly small: forwarders (L6), re-exports serving tests (L3),
three copies of the target-slot mapping (L5), and a page-list parser used
past its owner (L4).

### 2. Correctness and robustness

- Daemon lifecycle: the spawn cannot observe an early exit (M4); the idle
  quit lacks the start-time guard the other kill paths have (M2); request
  framing is trusted (L12). The health thread, sequential accept loop,
  `flock`-serialised spawn and idle timeout are sound as read.
- Unix-socket broker: McpBroker's id remapping and timeout handling are
  correct as read; DaemonClient skips stale ids correctly; the only gap is
  the non-object frame (L12) and the socket path length (M4/L10).
- MCP Subprocess JSON-RPC: floating `@latest` server against a pinned
  protocol version and a regex on its text output (H4).
- CDP session handling: two clients with different error models (M1); the
  curated CLI transport is pinned to tab 0 (M8).
- Active Page re-resolution: PageSelection is correct as read; URL-keyed
  resolution picks the first of two same-URL tabs (documented in the
  glossary); the parser is duplicated (L4).
- Interstitial detection: duplicate entries after exhausted retries, a
  hardcoded delay in the message, and one uncaught error class (L7).
- Supervisor (#52-#56): the never-hold-a-document-paused rules are
  implemented as described (discovery not auto-attach, resume before mark,
  watchdog with freeze detection, port-based retire). Remaining items are
  the missing `start_new_session`, the private `_connected` read and the
  stale "border" vocabulary (L9, M11).
- mode='real': broken on macOS whenever the state file is gone (H3).

### 3. Security

- Subprocess and shell: every spawn is list-form; no `shell=True`,
  `os.system` or `os.popen` (rung 2, grep over `src/`). `uv` and `lsof`/`ps`
  are resolved from `PATH` under the user's own environment.
- Socket: `0o600` after bind, small race (L10); the Daemon accepts any
  local process that can reach the socket, which is the stated trust model.
- Profiles and user-data-dirs: MCP-front dirs are `0o700`; CLI-front dirs
  live in `/tmp` with default umask (H1); profile names are not validated
  on the create path (H1, rung 4 traversal); `.browser-tools.json` from a
  cloned repository can select the endpoint and the profile (H2, rung 4).
- Env and credentials: reads are limited to
  `BROWSER_TOOLS_ALLOW_REMOTE_ENDPOINT`, `BROWSER_TOOLS_ENGINE`,
  `BROWSER_TOOLS_REGISTRY`, `BROWSER_TOOLS_PROFILES_DIR`,
  `TOOL_PROXY_PROJECT_DIR`/`CLAUDE_CWD`, `TOOL_PROXY_PROJECT_ID`/
  `CLAUDE_PROJECT_ID`, `WINDOWID`; state files are written `0o600`
  atomically. Cookie values are echoed by `get_frame_storage` (M9) and
  `get_cookies` (by design). Relative output paths land in the package
  checkout (M9). The MCP Subprocess is an unpinned remote package (H4).

### 4. Test coverage

871 tests pass under the CI command; overall coverage 56 %, with the
CLI-front modules (`cli`, `curated`, `passthrough`, `events`, `list_verbs`,
`one_shot`, `native_*`) at 91-99 % and the Daemon path
(`mcp_daemon` 35 %, `daemon_supervisor` 37 %, `mcp_broker` 25 %) plus the
vendored `core/attach` (26 %) and `core/registry` (48 %) at the bottom. The
one file that exercises McpBroker and DaemonClient is excluded from CI and
passes in under a second (M10). `pyright` covers `src/` only. Untested
paths are named in M10.

### 5. Tooling and hygiene

`pyproject.toml` is coherent (websockets-only default, extras for camoufox
and profiling, `core/` excluded from ruff and pyright per the RFC).
Gaps: `ruff format` is a pre-commit hook but not a CI check and 29 files
differ; `.pre-commit-config.yaml` pins ruff `v0.9.0` against a dev
dependency of `>=0.16`; `pyright` is not run on tests; `ci.yml` and
`release.yml` run different test sets; `Typing :: Typed` without
`py.typed`; `__version__` and `SECURITY.md` say 0.1.x while the package is
0.2.0; `.lucid/` and `assets/` are untracked; README Quick Start does not
run and the architecture sections of README and CONTRIBUTING describe the
pre-RFC module graph (M11, H5).
